# astral studio — project intake

this folder is your starting point. fill it out and send it back, and we start building.

## how to use this template

1. **fork or clone** this repo (or download the zip)
2. **fill in each numbered markdown file** in order. answer what you can. skip what you don't know — we'll cover those gaps on a call.
3. **drop supporting files** into the right `files/` subfolder (see below)
4. **send the whole folder back** (zip, github repo, or shared drive — whatever's easiest)

## what's in here

```
01-project.md       — what is this app?
02-audience.md      — who is it for?
03-brand.md         — visual direction
04-features.md      — mvp feature list
05-constraints.md   — stack, budget, timeline, hard lines
06-access.md        — credentials and accounts (DO NOT SEND IN ZIP — share privately)
07-competitors.md   — who else does this
08-success.md       — what "done" looks like

files/
├── brand/              — logo, colors, fonts, style guide
├── reference-designs/  — screenshots of apps/sites you love
├── content/            — copy, bios, product photos, anything to include
└── data/               — existing spreadsheets, customer lists, exports
```

## three rules

1. **be specific, not polished.** "i want it like airbnb but for yoga retreats" beats three paragraphs of marketing-speak.
2. **skip what you don't know.** a "not sure yet" is a useful answer. blank answers slow us down; invented ones break the build.
3. **never put secrets in the zip.** `06-access.md` is for listing WHICH accounts you'll grant access to, not the passwords. send those through 1password or signal.

## what happens next

1. we review the filled intake
2. 45-min call to close the gaps
3. we write your `INTAKE.md` — the one-page synthesized brief
4. that brief becomes the spec for an autonomous build loop
5. you get weekly demos and a working app in 3-4 weeks
